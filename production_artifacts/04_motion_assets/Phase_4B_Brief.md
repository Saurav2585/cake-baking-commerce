# Phase 4B Brief

## Objective

Define Pantryform’s complete motion language and production-asset blueprint, and demonstrate representative motion in a separate review-only prototype without beginning production engineering or bulk asset generation.

## Approved inputs

- Phase 1 findings and confirmed D-010–D-017.
- Approved Phase 2 brand/catalog architecture and D-020/D-022.
- Binding Phase 3 UX at `1b0c5fa60a0b50290cad6bf5bb3ec5de3ee55d01`.
- Approved Phase 4A “The Measured Pantry,” semantic system, high-fidelity specifications and five signature moments at `ab52b1bc600fbfda2793a1587a513dbd3329ca9e`.
- Phase 4B authorization: motion expresses raw ingredient → precise measure → method → joyful make while all facts/actions remain complete without it.

## Scope

- Semantic motion principles/tokens, five-signature choreography, page/component maps, scroll/viewport contract, reduced/no-animation contract and measurable performance budget.
- Production asset-family strategy, fictional packaging/label framework, representative product asset matrix, implementation-ready manifest schema and bounded Phase 5 pilot brief.
- Separate `design_review/phase_4b/` enhancement layer with full/reduced/no-animation and deterministic capture states.
- Before/mid/final, desktop/mobile, reduced-motion and component/state visual evidence.

## Exclusions

No production application, GSAP/Lenis dependency decision, production motion implementation, database, authentication, real checkout/payment/fulfilment, catalog population, full asset pilot or bulk generation. Phase 4A substantive evidence remains immutable; only its readout gate metadata may record the external approval.

## Dependencies and gates

- Engineering must treat Phase 4A HTML here as review scaffolding, not application foundations.
- Phase 5 may create only a separately authorized pilot from `Asset_Pilot_Brief.md`; bulk generation remains gated after pilot review.
- Phase 6 engineering consumes approved tokens/contracts and must remeasure runtime performance/accessibility.
- Asset factual inputs must come from approved catalog records; manifest validation fails closed.

## Acceptance criteria

- All sixteen required artifacts exist and are internally consistent.
- Every signature, page and required component has full, reduced-motion, no-animation and no-JavaScript behavior with cancellation/focus rules.
- Prototype demonstrates all eleven requested motion moments without changing Phase 3/4A meaning or performing real commerce.
- Motion resources stay bounded, interruptible and latest-state-wins; native scroll is preserved.
- Asset plan includes every required family; packaging spans seven merchandise departments; matrix covers eight representative content types; manifest contains every provenance field.
- Browser checks pass all eight widths, 320px, 200% text, reduced/off modes, rapid actions, interruption, resize/orientation, console and horizontal-overflow review.
- Evidence manifest records deterministic route, viewport, state and capture method; no unnecessary heavy recording is added.
- Generic-motion test passes and no unsupported claim, untracked generated asset or downstream implementation is introduced.
